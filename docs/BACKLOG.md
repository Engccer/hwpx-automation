# 백로그

## 착수 순서

| 순서 | 항목 | 필요 환경 | 규모 |
|---|---|---|---|
| 1 | #15 Windows 실측 | Windows(PowerShell) + JDK 21 | 작음 |
| 2 | #14 여러 문서 합치기 | Windows + 한컴오피스 COM | 중간 |
| 3 | #16 종이 인쇄(여러 부·양면) | Windows + 한컴오피스 COM + 실제 프린터 | 중간 |

## 열린 항목

- **#15 Windows 실측**: `convert/hwp2hwpx.bat`에 두 번째 인자가 기존 폴더면 그 안에 `<입력 이름>.hwpx`로 저장하는 분기를 넣었다(맥 `.sh`는 같은 동작을 시험으로 고정). Windows PowerShell에서 폴더(끝 `\` 있음·없음)·파일·생략 세 경우와 한글·공백 경로를 실측하고 이슈를 닫는다.
- **#14 여러 HWP/HWPX를 한 파일로 합치기**: 이슈의 실측 방법(pyhwpx `insert_file`, `BreakPage` 금지, 합본 쪽수·`BinData/` 수 대조)으로 `hwpx_com.py --append`를 만들고 SKILL.md 의사결정 트리에 한 줄을 넣는다. 한컴 COM이 없는 환경의 HWPX 수준 병합은 별도 판단.
- **#16 종이 인쇄 절차**: `hwpx_com.py`에 인쇄 명령(`--printer`·`--copies`·`--duplex`·`--dry`)을 만든다. 양면은 HPrint가 아니라 프린터 드라이버 `DuplexingMode`를 조회·변경·복원하고(사용자 PC 설정 변경이라 사용자 확인), 대기열 쪽수를 대조해 보고한다. 물리 출력은 되돌릴 수 없으므로 실행 전 부수·프린터·양면을 한 줄로 보고한다.

## 감시 항목 (조건이 생기면 처리)

- **rhwp 재직렬화의 진짜 변화 2종**: 한컴 저장 문서 12건 왕복에서 그림 `thumbnailBinIDRef` 소실과 필드 끝(`fieldEnd`) 위치 이동이 1건씩 나와 게이트가 거부한다. rhwp v0.8.7의 실측 한계다. rhwp 새 판에서 재측정하고, 사라지면 이 항목을 닫는다. 늘어나면 상류에 보고한다.
- **차트 든 문서의 교차 대조 실측**: `cross_check`는 `Chart/` 파트 내용 해시까지 대조하지만 차트가 든 표본이 없어 rhwp·JAR 변환물(HWP 입구), 원본과 JAR 왕복본(`--to-hwp`)의 차트 파트 바이트가 같은지 확인하지 못했다. 특히 `--to-hwp`는 차트 든 문서를 늘 거부할 가능성이 크다(리뷰 추정). 표본이 생겨 정상 문서가 거부되면 차트 파트 비교를 바이트에서 정규화된 XML로 바꾼다.
- **암호 HWPX의 rhwp PDF 해제 실측**: `--to-pdf --password`가 rhwp `--password-stdin`으로 암호 문서를 푸는지 표본이 없어 확인하지 못했다. 실패 안내는 Windows `--pdf-backend com`을 가리킨다. 암호 표본이 생기면 재고 `reference/rhwp.md` 폴백 표를 맞춘다.
- **한컴 2024 실사용 확인 결과 반영**: 위원장 실사용 확인(PROGRESS "실기 확인 대기")에서 열리지 않거나 위치가 어긋나는 문서군이 나오면 그 축을 COM 폴백 기본으로 되돌리고 CLAUDE.md에 사유를 적는다.
